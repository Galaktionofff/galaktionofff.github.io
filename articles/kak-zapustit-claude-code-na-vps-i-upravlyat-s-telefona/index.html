Как запустить Claude Code на сервере и управлять им с телефона?

Ноутбук закрылся — агент пропал. Перенос Claude Code на VPS решает только половину проблемы: процессу ещё нужен постоянный запуск, а сообщениям с телефона — защищённый канал. Иначе вместо карманного помощника получится открытый терминал на чужой машине.

В демонстрации Нейта Херка агент работает на облачном сервере и отвечает через бота. Я бы повторял этот сценарий не по рекламному таймеру «10 минут», а по контрольным точкам: вход, связь, права, восстановление после перезагрузки.

Сервер держит сессию, а телефон служит только окном для сообщений.

Сначала решите, нужен ли вообще бот

Самый короткий маршрут — VPS с установленным Claude Code, SSH-доступ и рабочий каталог проекта. По официальной документации каналов, Telegram-плагин не обязателен для работы самого агента. Если вы подключаетесь к серверу с ноутбука по SSH, на этом настройку можно остановить. Бот нужен, когда хочется отправить задачу с телефона и получить ответ там же.

В ролике Херк выбирает образ VPS с предустановленным Claude Code, проверяет tmux и обнаруживает, что bun отсутствует. Это разные зависимости: Claude Code запускается без Telegram-канала, а официальные плагины каналов требуют Bun. Предустановка у хостера не заменяет авторизацию Anthropic; вход через подписку или API настраивается отдельно. Цена VPS тоже отдельна от оплаты модели. Обещание, что «сервер никогда не выключается», я бы сразу заменил проверкой сервиса после рестарта.

Подключите канал, не отдавая сервер всему чату

Последовательность у Anthropic конкретная: создать бота в BotFather, установить telegram@claude-plugins-official через /plugin install, передать токен команде /telegram:configure, затем перезапустить Claude Code с --channels plugin:telegram@claude-plugins-official. После первого сообщения бот выдаёт код сопряжения; его подтверждают командой /telegram:access pair <code>, после чего ставят /telegram:access policy allowlist. Если бот молчит, первым делом проверьте, жив ли процесс с флагом --channels.

Одного токена бота мало: доступ к агенту заканчивается проверкой отправителя.

Я бы не переносил из демонстрации совет складывать пароль root и токены в проектный .env, который агент может прочитать или случайно отправить в репозиторий. Секреты держите вне проекта в хранилище с ограниченным доступом; для SSH используйте отдельного пользователя и ключи, а права агента на файлы и команды ограничьте. Список разрешённых отправителей фильтрует входящие сообщения, но не превращает выполняемые команды в безопасные. Присланный извне текст всё равно способен содержать вредоносные инструкции.

Проверьте не приветствие, а отказоустойчивость

У Херка бот отвечает после настройки, а затем после перезапуска VPS: для его конфигурации создан фоновый сервис. Это важнее первого красивого ответа. tmux сохраняет терминальную сессию при разрыве SSH-соединения, но сам по себе не гарантирует запуск после перезагрузки машины. Нужно проверить, какой сервис поднимает Claude Code, с какими правами он работает и где смотреть его журнал. Название службы из чужого видео копировать вслепую не стоит.

Моя проверка была бы приземлённой: отправить тестовое сообщение, убедиться в ответе, перезагрузить VPS, повторить сообщение и проверить, что посторонний аккаунт не получает доступ к агенту. Затем остановить канал и убедиться, что бот перестал отвечать. По документации события приходят только пока открыта сессия Claude Code; постоянно включённый VPS без запущенного процесса не поможет.

Херк предлагает понизить порог автосжатия контекста до 400 тысяч и называет 960 тысяч значением по умолчанию. Я не стал бы переносить эти числа в рецепт без сверки с документацией установленной версии и вашей модели: пределы контекста и поведение длинной сессии меняются. Надёжнее завести отдельные задачи и хранить важные решения в файлах проекта, не полагаясь на бесконечную историю чата.

Когда такая связка оправданна

Мне нравится идея телефона как пульта для уже настроенной рабочей среды: можно спросить статус сборки или запустить ограниченную процедуру без ноутбука. Но root-доступ, живой бот и полный набор API-ключей в одном сеансе — плохая цена за удобство. Сначала проверьте SSH-версию без канала. Потом добавляйте бот, сопряжение и фоновую службу по одному, с проверкой после каждого шага.

А какую задачу вы действительно доверили бы агенту с телефона без ручного подтверждения — просмотр логов, запуск тестов или изменение рабочего сервера?
