Mistral Large 4: открытые веса не отменяют счёт за сервер

Mistral открыла веса Large 4, она же Le Chonk: модель примерно на триллион параметров теперь можно скачать и запустить вне API компании. Я прочитал анонс и документацию. Событие серьёзное, но совет «забирай бесплатно и экономь» здесь хочется остановить ещё до аренды видеокарт.

У этой свободы два разных ценника: оборудование и условия лицензии. Если ты собираешь рабочую автоматизацию, проверить придётся оба.

Доступные для скачивания веса оставляют владельцу расходы на их запуск.

Экспертов включают выборочно, хранить нужно больше

В карточке модели указаны 1,05 трлн параметров всего и 52 млрд активных. Это MoE — «смесь экспертов»: на очередном шаге генерации работают выбранные блоки, а не вся модель целиком. Вычислений требуется меньше, чем при использовании всех параметров на каждом токене.

Но 52 млрд активных — не размер всей модели в памяти. Следующему токену могут понадобиться другие эксперты. Их подгрузка тоже стоит времени.

Проверим только порядок величин. При условных 4 битах на каждый из 1,05 трлн параметров сами веса занимают около 525 ГБ в десятичном счёте. Это арифметическая оценка, не измеренный размер готовой сборки: она не учитывает служебные данные квантования, память для контекста и работу движка.

Поэтому фраза «MoE поместится на паре GPU» без ёмкости памяти ничего не объясняет. Квантование сокращает объём хранения, а качество после сжатия нужно проверять на своих задачах.

52 млрд активных параметров описывают вычисления на шаге, а не полный объём хранимых весов.

Сначала сравни с API той же модели

В анонсе открытых весов Mistral указывает тариф: $0,70 за миллион входных токенов, $0,07 за миллион кешированных входных и $2,10 за миллион выходных. Это уже другой разговор, чем сравнение собственной аренды с произвольно дорогой закрытой моделью.

Условный пакет из миллиона обычных входных и миллиона выходных токенов обойдётся в $2,80 по этим ставкам. Без скидок, дополнительных сервисов и повторных попыток. Это расчёт по прайсу, не мой счёт за тестирование.

У своего развёртывания оплачивается время оборудования, включая простой. К нему добавляются запуск, наблюдение за сбоями и восстановление. Дешёвая прерываемая аренда может помочь, но тогда нужно переживать потерю машины и повторную загрузку весов.

Я считаю, что начинать стоит с проверки качества через API. Для моих сценариев в Hermes и n8n важен результат на конкретной задаче, а не факт владения большим файлом. Похожую экономику инструментов я обсуждаю в разборах ИИ и автоматизации: где появляется польза, а где только новая обязанность следить за сервером.

Скачать можно, условия всё равно действуют

Ещё одна причина не спешить: у Large 4 не обычная MIT-лицензия. В тексте лицензии есть отдельное условие для компаний, которые сами или через аффилированные организации ведут бизнес Model-as-a-Service — предоставляют доступ к моделям как услуге.

Для них перед коммерческим использованием модели требуется отдельная коммерческая лицензия Mistral. При этом документ отдельно исключает из этого требования внутреннее использование и использование через официальные продукты Mistral. В определении Model-as-a-Service также есть исключения, включая продукты со строго встроенными функциями модели и простую пересылку запросов к чужому хостингу.

Значит, собственный сервис с доступом к модели, встроенный помощник и внутренняя обработка документов могут попадать в разные условия. Скачанный файл сам по себе не снимает лицензионные обязательства. Для спорной бизнес-схемы нужен разбор условий, а не уверенность из слова «открытая».

Когда свой запуск имеет смысл

Я поддерживаю выпуск весов: можно выбирать инфраструктуру. Но без цифр на руках обещать экономию в четыре раза я бы не стал.

Начни с небольшой выборки своих задач. Зафиксируй долю принятых результатов, число переделок и задержку. Затем сравни стоимость этого же объёма через API с арендой оборудования и поддержкой собственного запуска. Отдельно проверь, разрешает ли лицензия именно твой способ использования.

Для редких запросов API может оказаться разумнее. Для постоянной нагрузки или требований к размещению данных стоит считать собственный контур.
