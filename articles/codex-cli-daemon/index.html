Codex CLI 0.157.0: как скрытый демон съедает гигабайты и ломает сессии

13 октября 2026 · 4 мин чтения

Всё началось с обычного рабочего дня: вы запустили Codex CLI в терминале, поработали, закрыли сессию — а процесс живёт дальше. Новая версия CLI (v 0.157.0) по умолчанию запускает app‑server daemon, который сам обновляется и хранит копии всех прошлых билдов в ~/.codex/packages/. Один пользователь уже наблюдал рост этой папки до ~12 ГБ, а каждый бинарник весит около 300 МБ. На фоне такой «тихой» активности ваши ресурсы тают незаметно.

Что происходит под капотом

С версии 0.156.0 автозапуск демона был opt‑in. Начиная с 0.157.0 разработчики сделали его включённым по умолчанию для интерактивных запусков. При каждом запуске CLI проверяется наличие актуального демона, при отсутствии — он скачивается и стартует. После старта он периодически проверяет наличие новых билда‑пакетов, скачивает их и заменяет текущий исполняемый файл без вашего участия.

Последствия в реальном пайплайне

  • Накопление «хвостов». Папка ~/.codex/packages/ растёт без ограничений: каждый минорный апдейт добавляет новый ~300 МБ бинарник. При длительной работе можно легко собрать десятки гигабайт мусора.
  • Фоновая жизнь после выхода. Демон остаётся в памяти и после закрытия терминала: он продолжает сам себя обновлять, тратя трафик и ресурсы машины без вашего ведома.
  • Разрыв сессии. Автообновление иногда «перепрыгивает» через версию, несовместимую с текущим клиентом, из‑за чего работа в терминале падает с ошибкой. Об этом пишут в issue #51763.
  • Блокировка `.git`. При обновлении демона могут появляться временные файлы с правами read‑only, из‑за чего Git‑операции завершаются с ошибкой, как описано в issue #52251.

Как отключить и очистить «присутствие»

Если вы предпочитаете контролировать обновления вручную, достаточно выключить автозапуск:

[features]
# отключаем автоматический запуск демона
daemon_auto_start = false

Или воспользоваться встроенной командой:

codex features disable daemon_auto_start

После этого остановите уже запущенный процесс:

codex app-server daemon stop

И удалите накопившиеся пакеты:

rm -rf ~/.codex/packages/*

Вывод

Автоматический фон может быть полезен: он гарантирует, что у вас всегда самая свежая версия инструмента. Но, как любой «тихий» процесс, он требует осознанного управления. Отключите автозапуск, регулярно чистите ~/.codex/packages/ и следите за появлением новых версий. Иначе ваш терминал может превратиться в скрытый «тихий хищник», который беззвучно пожирает ресурсы и ломает рабочие сценарии.
